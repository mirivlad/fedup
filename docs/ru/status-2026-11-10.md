# FedUp — фактический статус и приёмка, 10 ноября 2026

Документ фиксирует только то, что реализовано и проверено в коде. CI — не замена приёмке реальных устройств.

## Этап 1. Учётные записи и защищённый выпуск устройств — НЕ ЗАКРЫТ

- [x] Создание, отзыв и смена пароля пользователей, Argon2id, SQLite, ограничения попыток.
- [x] Android: сервер, логин, пароль; неэкспортируемый Keystore P-256 ключ и автоматический CSR без ручных файлов.
- [x] Привязка сертификата к ревизии пользователя, отзыв доступа и повторная проверка.
- [ ] Защищённый выделенный выдающий процесс с краткосрочным промежуточным CA (без online root key).
- [ ] Автоматическое продление, миграции, переключение пользователей, восстановление после сбоя.

## Этап 2. Реальный Android → VPS → интернет — НЕ ЗАКРЫТ

- [x] IPv4 TUN через mTLS/HTTP2; серверная SNAT и DNS; в изолированных Linux namespaces виден WAN IP шлюза.
- [x] Сервер выдерживает одно намеренно незавершённое TLS-соединение, не останавливая легитимный клиент (регрессионный тест).
- [ ] Реальное Android-устройство + отдельный VPS + проверка внешнего IPv4, DNS и нескольких HTTPS-сайтов.
- [ ] MTU, аварии, Wi-Fi/LTE, IPv6/DNS leaks и защита от падения туннеля.
- [ ] Безопасный systemd/deb и APK со стабильной подписью и обновлением.

## Этап 3. DPI и сетевой отпечаток — НЕ ЗАКРЫТ

**Новый эксперимент:** Caddy HTTPS/2 → loopback-only h2c → защищённый app-proof → IPv4 NAT, также аутентифицированная конфигурация по логину/паролю. Подтверждено синтетическим CI #262 (7/7), но не публичным VPS/Android. См. [сводку третьего цикла](dpi-iteration-report-2026-11-10.md).

Реализованы экспериментальные улучшения: локальный настоящий HTTPS/2-контроль
(`nghttpd`/`nghttp`), сравнение ClientHello отдельно от разницы тестовых портов,
и публичный TLS 1.3 HTTPS-ответ по HTTP/1.1 либо HTTP/2 на анонимном
подключении к VPS. VPN остаётся доступен исключительно обладателю
авторизованного клиентского сертификата. Общее число завершённых TLS-сессий
и незавершённых рукопожатий ограничено отдельно.

**Это не полноценная маскировка:** публичный fallback пока слушает
TCP 7443, TLS сервер продолжает запрашивать сертификат (опционально),
что заметно активному проверяющему клиенту. Отдельное архитектурное решение:
[ADR-0002](../adr/0002-https443-application-device-proof.md).


- [x] Синтетические трёхсетевые трассы raw TLS и настоящего HTTP/2, повторные ClientHello/flow-измерения.
- [x] Локальное сравнение пассивно наблюдаемых TLS-признаков с контрольным curl/OpenSSL HTTPS/1.1.
- [x] Отказ анонимному активному пробнику, сохранение работоспособности действующего туннеля.
- [ ] Браузерная HTTPS/2 контрольная группа с сопоставимым содержимым и hold-out тестами.
- [ ] Отдельный захват именно Android/OkHttp. Нельзя переносить отпечаток Linux Rust на Android.
- [x] В отдельной экспериментальной ветке убран TLS CertificateRequest на публичном HTTPS, сохранены одноразовая подпись ключом и живой отзыв; протестированы Caddy/h2c и публичный веб при активном IP-туннеле.
- [ ] Принять внешний TCP 443 на отдельном VPS и физический Android; выполнить hold-out сравнение с настоящим HTTPS.

## Этап 4. Платформы и одновременные устройства — НЕ ЗАКРЫТ

- [x] Общая Rust IP-политика; экспериментальный Android VpnService; до восьми записей устройств на пользователя.
- [ ] Одновременные IP-сессии, адреса для каждого устройства, TUN demultiplexing, routing, NAT.
- [ ] Безопасная host-level Linux маршрутизация, DNS/kill-switch, сервис и настольный клиент.
- [ ] Windows Wintun/WFP, защищённое хранение ключей, инсталлятор и VM тесты.
- [ ] Android Always-on/Lockdown, стабильные APK обновления, тесты сна/роуминга, IPv6.

## Критерии приёмки

1. Из браузера физического телефона виден публичный IPv4 личного VPS.
2. Соединения и DNS работают после разрыва/восстановления, не допускаются подтверждённые утечки.
3. Параллельно подключаются разные устройства и платформы без смешения пакетов.
4. DPI-оценка сообщает измеренные отличия и ложные срабатывания, а не выдуманный процент невидимости.

Пока нельзя выпускать production release. Для ограниченного теста — docs/ru/vps-first-ipv4.md. Задачи #8, #10, #12, #13.
