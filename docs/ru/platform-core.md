# FedUp: переносимое ядро IP-пакетов

## Что вынесено из Linux

В Rust workspace добавлен crate **fedup-core**. Он не зависит от Linux TUN, nftables, OpenSSL или реализации TLS и не использует платформенные сетевые API. Его задача — одинаковая проверка IP-пакетов независимо от транспорта и операционной системы.

В текущем лабораторном режиме \`IpPolicy::isolated_lab()\` задаёт строгие адреса:

- Клиент: 10.77.0.2 и fd42:fed0::2.
- VPN-сервер: 10.77.0.1 и fd42:fed0::1.
- Удалённый тестовый узел: 10.88.0.10 и fd42:fed1::10.
- MTU: 1280 байт.

Политика допускает пакет только при правильном направлении, указанном адресе источника и явно разрешённом адресе назначения. Проверяются версии и длины IPv4/IPv6; IPv4-фрагменты и опции заголовка, IPv6 расширения/фрагменты пока **отклоняются** — реассемблирования пакетов ещё нет. Добавлены тесты на недопустимые адреса, повреждённые длины, подмену источника и случайные входные байты.

**Linux fedup-tun теперь использует fedup-core в обоих режимах: raw TLS и настоящий HTTP/2.** Отдельный Linux валидатор удалён, поэтому расхождения между транспортами в проверке пакетов не должно быть.

## Проверка переносимости

В GitHub Actions код компилируется для:

- Linux (плюс unit tests),
- x86_64-pc-windows-gnu,
- aarch64-linux-android.

~~~bash
cargo test -p fedup-core
rustup target add x86_64-pc-windows-gnu aarch64-linux-android
cargo check -p fedup-core --target x86_64-pc-windows-gnu
cargo check -p fedup-core --target aarch64-linux-android
~~~

Это **не готовые сборки Windows или Android**: \`cargo check\` проверяет только переносимый Rust-код, а не запуск на телефоне/Windows. Для практического клиента потребуются отдельно адаптеры системного VPN API, защищённое хранение ключей, жизненный цикл соединения, маршруты, DNS и платформа-специфичная политика отказа.

## Архитектурные границы

- **fedup-core:** единые правила IP-пакетов и последующая логика общих сеансов.
- **fedup-protocol:** независимые бинарные кадры и их ограничение размера.
- **fedup-tun:** только Linux TUN и лабораторная сеть.
- **fedup-netguard:** только Linux nftables и лабораторный fail-closed.
- **Windows:** будущий адаптер Wintun/сетевого интерфейса и WFP.
- **Android:** будущий адаптер VpnService и системной постоянной VPN/Lockdown.

Нельзя путать переносимость библиотеки с готовностью платформенного VPN или с защитой от DPI. Ни IP ACL, ни kill switch не маскируют TLS/HTTP-транспорт.
