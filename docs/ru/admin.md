# FedUp: управление устройствами по SSH

Добавлена программа **fedup-admin** для Linux. Она управляет списком клиентских сертификатов, которым разрешено подключаться к экспериментальному серверу FedUp. Пока это не полноценная регистрация устройств и не готовый VPN.

## Как проверить

Из каталога репозитория на Debian / MX Linux:

~~~bash
git pull
cargo build -p fedup-admin -p fedup-link
cargo test --workspace --all-targets
bash tests/link-smoke.sh
~~~

Последний сценарий сам создаёт временные тестовые сертификаты, проверяет TCP-передачу, отказ чужому клиенту и отзыв доступа у уже подключённого устройства. Для него не нужен VPS.

## Управление

~~~bash
# Создать список разрешений (если файла ещё нет)
target/debug/fedup-admin init /etc/fedup/allowed.txt

# Добавить устройство по его ПУБЛИЧНОМУ сертификату
target/debug/fedup-admin add /etc/fedup/allowed.txt my-phone /path/to/phone.pem

# Показать все разрешённые устройства
target/debug/fedup-admin list /etc/fedup/allowed.txt

# Отозвать доступ
target/debug/fedup-admin revoke /etc/fedup/allowed.txt my-phone

# Получить отпечаток сертификата
target/debug/fedup-admin fingerprint /path/to/phone.pem
~~~

Каталог /etc/fedup нужно предварительно создать и ограничить права на него. Для административных операций может потребоваться sudo.

У каждого клиента должен быть свой отдельный сертификат, подписанный доверенным центром (CA) сервера. Программа принимает только **публичный сертификат**; закрытый ключ должен оставаться на клиентском устройстве. Сам fedup-admin сертификаты пока не выпускает.

## Что сделано

При добавлении и отзыве программа блокирует параллельные изменения, проверяет записи и записывает новый файл с правами 0600. Старый файл заменяется атомарно, без промежуточной частично заполненной конфигурации.

Сервер FedUp использует тот же список. После отзыва он не принимает новые подключения устройства и периодически проверяет уже открытые соединения (каждые пять секунд). Полноценной системы распределения отзыва по нескольким серверам пока нет.

## Что впереди

Одноразовые приглашения, создание ключей непосредственно на клиенте, выпуск сертификатов, аудит изменений, роли и веб-панель. В текущем виде это **только проверяемый административный инструмент для лабораторного транспорта**.

Не публикуй реальные ключи, сертификаты действующих устройств и адреса серверов в GitHub. Сам список содержит отпечатки сертификатов, но тоже является служебной конфигурацией.
