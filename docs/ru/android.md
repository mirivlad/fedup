# FedUp для Android — автоматическая регистрация и тестовый IP-туннель

Android-проект в каталоге android/ собирается в debug APK с нативным Rust-модулем fedup-core. Это **экспериментальная программа**, не готовая к защите обычного интернета или регулярному использованию в сети с блокировками.

## Обычный интерфейс

На главном экране пользователь вводит **адрес HTTPS-сервера, логин и пароль** и нажимает «Войти и зарегистрировать телефон». После проверки учётных данных приложение:

1. По обычному публично доверенному HTTPS получает публичный CA сертификат для будущего VPN и его SHA-256.
2. Создаёт неэкспортируемый приватный ключ P-256 в Android Keystore.
3. Формирует и подписывает PKCS#10 CSR локально.
4. Передаёт только CSR, имя устройства и логин/пароль на сервер.
5. Проверяет подписанный CA, срок, EKU clientAuth, DigitalSignature и совпадение публичного ключа с ключом Android Keystore.
6. Сохраняет сертификат и зашифрованный под AES-GCM/Keystore пароль.

Обмен CSR и PEM файлами пользователю не требуется. Если связь пропала до получения сертификата, повторная попытка использует тот же локальный ключ/CSR, а сервер возвращает ранее выданный сертификат.

**Сертификат пока выпускается только в специально разрешённом небезопасном лабораторном режиме.** На рабочем VPS должно использоваться отдельное защищённое удостоверяющее звено, а не plaintext-ключ CA в приложении авторизации.

## Лабораторный VPN

В расширенной диагностике есть запуск настоящего Android VpnService с TUN и двунаправленной передачей IP-пакетов через взаимно аутентифицированный TLS 1.3 / HTTP/2. Сокет до сервера защищается VpnService.protect() перед установлением соединения. Трафик фильтруется через Rust fedup-core, размер пакета ограничен 1280 байтами.

**Здесь нет маршрута по умолчанию, перехвата системного DNS и защиты всего интернета.** Туннель разрешает только адреса: 10.77.0.1, 10.88.0.10, fd42:fed0::1, fd42:fed1::10. Для его включения требуется явное разрешение Android и подтверждение пользователя о замене прежнего VPN. Android Always-on объявлен неподдерживаемым, Lockdown не включается.

На физическом телефоне новая цепочка ещё не испытана. CI доказывает только корректность сборки JNI/Kotlin и модульных тестов, а сетевые сквозные сценарии пока выполняются в изолированных Linux namespaces.

## Сборка Android

Нужны Android SDK 35, NDK 27.2.12479018, Gradle 8.13, JDK 17, Rust Android ARM64 target и cargo-ndk.

~~~bash
rustup target add aarch64-linux-android
cargo install cargo-ndk --locked
export ANDROID_NDK_HOME="$ANDROID_HOME/ndk/27.2.12479018"
cargo ndk -t arm64-v8a -o android/app/src/main/jniLibs build --release -p fedup-android
cd android
gradle --no-daemon :app:assembleDebug :app:testDebugUnitTest
~~~

GitHub Actions сохраняет одноразовый debug APK как артефакт. Он подписан временным debug-ключом и **не подходит для стабильного обновления или боевого VPN**.

## Осталось до реального Android VPN

- Защищённый отдельный издатель клиентских сертификатов, обновление и ротация ключей и сертификатов, переключение пользователей.
- Настоящая серверная маршрутизация всего интернета, DNS и IPv6 с системной политикой обхода/утечек и корректной работой Always-on/Lockdown.
- Проверки в Android Emulator и на физических телефонах, смена Wi-Fi/LTE, сон, аварии, блокировка, отзыв устройств и обновление подписанных APK.
- Проверка реальной устойчивости транспортов к DPI на собственных контролируемых стендах без обещаний «невидимости».

Подробная инструкция по серверным пользователям и автоматическому выпуску устройств: [учётные записи](accounts.md).

Системный API: https://developer.android.com/develop/connectivity/vpn .
