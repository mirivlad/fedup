# FedUp — первый TCP-транспорт

Это **эксперимент, не полноценный VPN**. Теперь приложение fedup-link действительно передаёт TCP-данные через TLS 1.3 между двумя Linux-машинами. Однако оно не создаёт TUN-интерфейс, не меняет маршруты и не умеет передавать произвольные IP-пакеты.

~~~text
Программа на ПК
     |
127.0.0.1:CLIENT_PORT
     |
fedup-link client
     |
 mTLS 1.3
     |
fedup-link server
     |
127.0.0.1:TARGET_PORT
     |
Сервис на сервере
~~~

## Реализовано

- Двусторонняя передача TCP (включая бинарные данные).
- Проверка сертификата сервера и отдельного клиентского сертификата.
- Список SHA-256 отпечатков разрешённых клиентских сертификатов.
- Удаление отпечатка блокирует новые сессии и отключает активные примерно в пределах интервала повторной проверки 5 секунд.
- Ограничения памяти, размера кадров и числа одновременных подключений.
- Клиент слушает только локальный интерфейс. Сервер по умолчанию также слушает только локальный адрес; внешний интерфейс требует явно заданного флага. Цель перенаправления ограничена loopback на стороне сервера.

## Проверка

Требуются Linux, Rust, OpenSSL, Python 3.

~~~bash
git clone https://github.com/mirivlad/fedup.git
cd fedup
cargo test --workspace --all-targets
cargo build -p fedup-link -p fedup-admin -p fedup-identity
bash tests/link-smoke.sh
~~~

Скрипт создаёт одноразовые сертификаты, запускает локальный echo-сервис, проверяет передачу данных и блокировку отозванного/чужого клиента, затем удаляет временные ключи.

Для зарегистрированного Linux-устройства предпочтительна команда client-device: она сама берёт имя сервера, доверенный CA и сертификат из каталога устройства, открывая зашифрованный ключ только в памяти:

~~~bash
target/debug/fedup-link client-device 127.0.0.1:8000 SERVER_IP:PORT ./my-device
~~~

Подробнее — в [инструкции по клиентским ключам](device.md).

Синтаксис старого стендового запуска:

~~~text
fedup-link fingerprint CLIENT_CERT.pem

fedup-link server LISTEN_IP:PORT 127.0.0.1:TARGET_PORT ca.pem server.pem server.key allowlist.txt [--allow-public-bind]

fedup-link client 127.0.0.1:CLIENT_PORT SERVER_IP:PORT SERVER_NAME ca.pem client.pem client.key --unsafe-lab-plaintext-key
~~~

Полное описание: [английская техническая документация](../tcp-link.md).

**Не публикуй реальные сертификаты, ключи и адреса серверов.** Для ручной проверки на двух хостах используем частную лабораторную сеть, а не публичный рабочий VPS. Незаметность для DPI пока не измерялась. Сейчас это TLS-транспорт, но **не HTTPS**.

Добавлена [экспериментальная SSH-утилита для управления списком устройств](admin.md), но создание и выпуск ключей по приглашениям пока не реализованы.

Следующее: безопасная выдача ключей, TCP/UDP сеансы, TUN, маршрутизация DNS/IPv4/IPv6 и нормальные клиенты.
